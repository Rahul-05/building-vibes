## 1. Listing-vs-record checker
- New mode on a building's results page (and reachable from landing after an address is chosen): "Check a listing" — a textarea where the visitor pastes a rental listing's text (apartments.com / StreetEasy / Craigslist copy). A line under it: "The text is sent to our AI helper to compare with the record. It isn't stored."
- Worker change (this phase DOES touch the Worker): add `POST /check` accepting `{ address, summary, listingText, language }`. Raise the body cap for this route only (listing text up to ~4,000 chars; total body ≤ 24KB). New instruction set: extract the listing's factual claims about the building/unit (quiet, renovated, laundry, elevator, heat included, no complaints, etc.) and line each up against the record summary. Output structured JSON: `{ pairs: [{ claim, record }], note }` where `record` states what the public record shows or "The record doesn't mention this." Same hard rules: never call the listing false/a liar, no verdicts, no advice — claims and record sit side by side. If the model returns non-JSON, fall back to a single text block (frontend renders it plainly).
- Frontend renders pairs as two-column cards ("The listing says" / "The record shows" — both labels come from the i18n dictionary), in the existing design language, with the standard disclaimer. Empty/irrelevant listing text → friendly "that doesn't look like a listing" state, no AI call wasted on gibberish (cheap length/keyword sanity check is fine).
- The existing model-race in the Worker should be reused for /check.

## 2. Language mode — ALL languages Google offers, free (user amendment, Oct 20)
Design (fixed): no runtime translation service, no new keys or accounts.
- **Language set:** the full Google Translate supported list (~240 languages). The selector is a SEARCHABLE dropdown: NYC's 11 (English, Español, 中文， Русский, বাংলা, Kreyòl Ayisyen, 한국어, العربية, اردو, Français, Polski) pinned at top under "Popular in NYC", then every other language listed by its own endonym. Choice persists in localStorage (display preference only).
- **UI strings, translated once at build time:** English source dictionary `src/i18n/en.json` covering ALL UI chrome (headings, buttons, section titles, flag labels, disclaimers, form labels, questions scaffolding, compare + checker labels, AND the "public-record information, not advice" line). A resumable script `scripts/translate-ui.mjs` reads the Gemini key from an env var (NEVER committed, never in the repo) and translates the dictionary into every target language in batches, writing `src/i18n/<code>.json`. Rules for the script: preserve `{placeholder}` tokens exactly; keep translations concise; validate JSON after each language; incremental (only missing keys translated) and resumable so free-tier quota can refill between runs; spread calls across the Worker's model list; log per-language success/failure. The app lazy-loads only the selected language's file; a language appears in the selector only if its dictionary file exists (English always).
- **Data-derived content** (violation/complaint descriptions from the city) stays in English as published — it is quoted official text; only the scaffolding around it translates.
- **AI content in the chosen language:** /story, /ask, /check payloads include `language` (English name + code). The Worker instructs the model to write its whole answer in that language. FOOTER CHANGE: the Worker stops appending the footer line; the FRONTEND appends the dictionary's translated "public-record information, not advice" line under AI text (identical visually, robust across 240 languages).
- **Verdict-ban enforcement:** English banned-word check stays; the model instruction (in English) states the no-verdict rule applies in every language; add banned equivalents for the NYC-11 languages where straightforward. Do not attempt exhaustive checks for all ~240.
- **RTL:** for RTL languages (Arabic, Urdu, Hebrew, Persian, Pashto, Sindhi, Uyghur, Divehi, etc.) set `dir="rtl"` on the app root; design must not break. **Formatting:** Intl.DateTimeFormat/NumberFormat with the selected locale where the UI formats values itself.
